# Team Scrum Agreement
This agreement defines how our team plans, executes, reviews, and delivers work during each sprint. Everyone follows the same rules to ensure transparency, quality, and teamwork.

## 1. Backlog & Task Definition

Tasks must be small, clear, and actionable (ideally ≤ 1 day of work).

Each task must have:
- A clear goal
- Simple acceptance criteria
- One primary owner
- Avoid vague tasks (e.g., “optimize model” without specifics).

## 2. Sprint Planning Rules
- Only tasks the team commits to are added to the sprint.
- Every task in the sprint must:
  - Be understood by the team
  - Have an owner
  - Be realistically achievable within the sprint
- If a task is unclear, it does **not** enter the sprint.

## 3. Daily Work & Progress Logging
- All meaningful work must be logged to the task (comments, commits, screenshots, links).
- Small progress is still progress → log it.
- If blocked for more than 1 working day, raise it immediately.

## 4. Task Status Workflow
We follow this workflow strictly:
```
To Do → In Progress → Testing → Review → Done
```
- ❌ Do NOT move tasks directly to Done
- ✅ Move tasks to Testing before review
- ✅ Review is done together as a team
- A task is Done only after:
  - Acceptance criteria are met
  - Team review is completed

## 5. Code & Review Standards
- Prefer small, focused PRs.
- No self-approval unless explicitly agreed.
- Reviews focus on:
  - Correctness
  - Readability
  - Impact on the team
- Quality > speed.

## 6. Meeting Discipline
**Sprint Review / Planning** (Thu 13:00 PM - 14:00 PM):
- Demonstrate working results
- Review tasks before marking them Done
- Plan what to do next Sprint

## 7. Ownership & Accountability
- Each task has one accountable owner.
- Owners are responsible for:
  - Keeping the task updated
  - Asking for help early
  - Moving task status correctly

## 8. Quality Definition of “Done”
A task is Done only if it:
- Works as expected
  - Has been reviewed
  - Is minimally documented if needed

“Almost done” = Not done

## 9. Communication Rules
- Over-communicate progress.
- If your work affects others, say it early.
- No surprise work at the end of the sprint.

## 10. Team Principles
- Small tasks beat big tasks
- Visibility beats perfection
- Raising problems early is good Scrum behavior
- Team success > individual speed
